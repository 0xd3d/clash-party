# Three-platform privacy architecture

Desktop and iOS live on the same branch. `apps/ios` contains the Swift app and Packet Tunnel extension; `modules/mihomo-ios-core` contains the reproducible, separately versioned mobile core. Desktop still uses its prepared Mihomo binaries. An iOS source merge does not establish identical core versions or universal profile compatibility.

## Shared protection target

While the user has enabled a protected tunnel, ordinary application DNS and TCP/UDP traffic should follow the effective profile; private/LAN and China/direct decisions happen inside that policy. The profile owns nodes, credentials, upstream DNS, outbound groups and deliberate exceptions. No production node, operator preference or private desktop snapshot belongs in application source.

| Platform | Implementation                                                                                                   | Important boundary                                                                                                                                                                  |
| -------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS    | Opt-in independent native PF traffic lease, private SGID core identity, verified TUN and loopback system DNS     | PF survives a core/app crash, not OS reboot. PF is not an Apple-supported product API; conflicting PF rules, skipped interfaces or ambiguous old states prevent a confirmed result. |
| Windows  | Opt-in independent WFP helper process, verified core AppID and Wintun LUID, IPv4/IPv6 filters                    | Dynamic filters survive core/app failure while the helper and BFE remain alive. Helper/BFE failure or OS reboot removes the dynamic session; this is not a boot-time kill switch.   |
| iOS      | NetworkExtension capture, failure-latched packet discard, proxy-bound business DNS and IPv4/IPv6 packet handling | Apple's system exceptions remain. Ordinary personal VPN is not enterprise Always On; explicit user stop/removal can restore direct networking.                                      |

Desktop protection is off by default and requires explicit activation in the TUN page of the new build. The fixed-purpose native helpers accept no profile scripts, firewall text, physical interface identifiers or arbitrary executable paths. An independent guard is armed before stopping an old core, and bound to the actual core and virtual adapter before protected startup reports success. Failed startup/reload and automatic restart retain the lease; explicit user stop, feature disable or normal app exit releases it. macOS DNS and traffic leases are independent, so DNS restoration cannot silently remove traffic protection. See the [source audit](network-protection-audit.md), [macOS helper](../integrations/macos-dns-guard-native/README.md) and [Windows helper](../integrations/windows-network-guard/README.md).

A common desktop runtime pass runs after overrides in both compilation paths. It preserves domestic TCP, LAN and the two authorized QQ Music DNS exceptions, binds encrypted business upstreams to a statically verifiable proxy-only target, and prevents empty-group or unsupported-UDP fallback to DIRECT. Independent node bootstrap uses encrypted literal-IP endpoints rather than depending on the node it resolves. Selecting the full public-UDP option also sends domestic public UDP through that target, covering arbitrary-port STUN; disabling it retains country rules for such UDP and cannot promise universal STUN containment. Stored subscriptions and provider endpoints are not rewritten. DNS providers and node credentials remain configuration data.

On iOS the same safety goals are implemented in its own runtime compiler and separately versioned mobile core. Proxy-only business DNS is validated; missing adapters, unsupported UDP and empty groups fail closed. Known resolver domains/IPs, DNS/DoT/DoQ and public UDP precede country shortcuts, while explicit private/LAN handling and QQ Music's exact DNS exception remain. A provider failure after connection keeps the packet tunnel and DNS settings and latches packet discard until a new explicit session. Ordinary user disconnect is still allowed.

Supported routing can be exported as a portable policy using the iOS tools; unsupported MRS is converted by the existing desktop core, never approximated by a new rule engine. Expansion is capped at 50,000 rules, so the current large desktop master profile cannot be synchronized in full through that exporter. Oversized profiles fail explicitly; iOS General Routing reuses compact GeoSite data and public YAML providers, while node credentials are imported independently. See the [iOS compatibility limits](../apps/ios/README.md#policy-and-supported-runtime).

## Browser boundary

A browser extension is optional defense in depth. Full routing/DNS interception is a system responsibility. The bundled Chrome/Edge extension additionally controls WebRTC IP handling per browser profile; Electron's setting covers only the app's own pages. Safari/iPhone does not offer the equivalent Chromium privacy API. Neither a visible extension switch nor the country count of recursive resolvers is proof of complete containment.

## Build and validation

Desktop CI builds native Windows/macOS x64 and ARM64 packages and publishes complete, gated Releases. The independent iOS workflow rebuilds its mobile core, runs Swift/Objective-C/Python/Go regressions and compiles unsigned device/simulator apps. Unsigned device artifacts are not installable signed IPAs. Local signing uses ignored `apps/ios/Config/Local.xcconfig`; CI never reads a personal Team, certificate, provisioning profile or node credential.

`apps` and `modules` are excluded from desktop ASARs; the package verifier checks this boundary. Frameworks, derived data, signing materials and downloaded Geo databases are excluded from Git. Source/build tests do not replace physical network validation.

Acceptance evidence must separately cover system DNS ownership, fresh LAN/public UDP/TCP 53 sockets, HTTP and WebRTC egress, real IPv6 transport, expected LAN access, Wi-Fi/cellular or interface changes, core failure/recovery and normal exit. Tests must retain configured DNS exceptions. Do not disable a required VPN or restart an active client merely to obtain a baseline.
