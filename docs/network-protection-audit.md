# Network protection source audit

This audit distinguishes source behavior, isolated build/protocol tests and real device enforcement. These changes do not activate protection in a currently running app, install a helper, alter a system firewall, change the operator's node or operate an iPhone. Desktop protection defaults to off and is enabled explicitly in the new build's TUN page.

Relevant desktop files are `src/main/core/{manager,factory,mihomoApi,networkGuard,networkProtectionPolicy,macDNSGuard,permissions}.ts`. Fixed native implementations are under `integrations/{windows-network-guard,macos-dns-guard-native}`. Mobile code is under `apps/ios` and `modules/mihomo-ios-core`; desktop continues to use its prepared upstream binaries.

The manager refuses detached/lightweight-core operation while protected. Protected startup waits for actual native binding, rather than only a log message. Mode changes away from rule mode and disabling active rules are rejected. Full reload, patch and standard/simple compilation all reapply protection after user overrides. The guard is armed before replacing a core or runtime; any validation/reload/binding failure retains blocking instead of releasing it. Normal user stop and disabling the feature are explicit recovery paths. Native commands are serialized; generation checks prevent an in-flight startup from rearming after an explicit stop.

## Preserved policy and deliberate tradeoffs

- Existing China TCP/direct rules remain in their original order after protection prefixes. Domestic direct traffic is sent by the trusted core, so it still works while physical application bypass is blocked.
- Private/LAN, loopback, link-local and required local discovery remain available. Physical plain TCP/UDP 53 is blocked before LAN exceptions; LAN services at other ports remain allowed. No physical interface name/index is hardcoded.
- Only `aqqmusic.tc.qq.com` and `+.stream.qqmusic.qq.com` retain the authorized `https://doh.pub/dns-query#DIRECT` DNS exception. Other business policies are bound to the protected target.
- Business DNS and proxy-node bootstrap are separate. Independent bootstrap requires encrypted literal-IP endpoints, preventing a recursive dependency on the node being resolved. These provider endpoints come from the profile, not a hardcoded operator choice.
- The desktop **all public UDP** option covers arbitrary-port STUN but also proxies domestic public UDP. Turning it off preserves domestic UDP country routing, with only known resolver/STUN destinations covered. Those two outcomes cannot simultaneously be described as universal STUN protection.
- A statically proven target cannot include DIRECT, COMPATIBLE, reserved global/DNS targets, cycles or opaque provider membership. All reachable groups use REJECT when filtering leaves no candidate. DNS URL fragments are decoded once; options are safely encoded and the sole selected proxy token is last.

## Limits that routing cannot remove

Application-owned encrypted DNS to configured/known resolvers is routed through the protected target. Unknown DoH sent to an otherwise ordinary domestic HTTPS endpoint cannot be identified universally without inspecting TLS or proxying all domestic HTTPS. The retained China-direct requirement therefore precludes an unconditional claim that every encrypted resolver is identified. An application choosing an arbitrary TURN/TCP endpoint under the same domestic HTTPS conditions has the same classification boundary.

STUN containment and browser address disclosure are related but different. Routing cannot prevent a browser from enumerating local host candidates. The optional bundled Chromium extension uses `disable_non_proxied_udp`, reads back ownership/status and restores only its own setting. It affects only the installed Chrome/Edge profile; it is not automatically installed and does not cover Safari/iPhone or Firefox. Electron's setting covers only Clash Party WebContents. Real browser ICE/HTTP/IPv6 results must still be checked.

macOS PF is not Apple's supported product API. Earlier quick-pass rules, skipped interfaces, unknown/NAT state readback or unproven core/socket ownership cause an unconfirmed result. Activation may close only strictly parsed, locally derived old public address pairs; ambiguous or mixed LAN DNS/application pairs are retained and reported, never globally flushed. Windows uses dynamic WFP filters, not persistent boot filters: helper/BFE death or reboot ends that protection. Ordinary iOS VPN cannot guarantee blocking after explicit user stop/removal or across Apple's system exceptions. No platform claims protection after every possible OS or privileged administrator action.

## Verification evidence

- TypeScript tests cover runtime DNS binding/fragment encoding, target proof, empty fallback, domestic/LAN/QQ preservation, rule ordering and independent native-session lifecycle/races.
- Native Windows x64 and ARM64 CI compiles the helper, verifies PE architecture and runs only pure protocol/policy fixtures. It does not open WFP or certify physical networking.
- macOS native ARM64 compile/self-tests and x64 typecheck exercise pure policy, ownership, dual-lease, old-state parsing and recovery cases. No live PF/group/installer operations are part of those tests.
- Mobile portable tests run the real checked-in Go policy/DNS/group code and Swift/Objective-C packet/DNS checks. Device and ARM64 simulator architectures compile unsigned. No signed install or phone runtime test is implied.
- `pnpm exec tsx scripts/check-desktop-protection.ts` uses isolated, unprivileged loopback-only desktop cores with TUN disabled. Its controlled direct traps establish the unsafe positive controls and safe DNS/UDP behavior. It neither modifies the running application nor tests an OS firewall.

Before claiming live enforcement, use a separate test environment to enable protection and verify core/app crash, IPv4/IPv6, arbitrary-port UDP/STUN, known Secure DNS, domestic TCP, LAN and QQ Music, explicit stop and recovery. Record unknown encrypted-DNS and OS/helper lifetime boundaries rather than treating a timeout or UI switch as proof. See [network validation](network-validation.md).
